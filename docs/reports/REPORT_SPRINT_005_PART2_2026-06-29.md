## Решение по спринту: закончили или оставили на потом?

**Спринт 5 формально не закрываем на 100%**, но **основные критерии готовности MVP корзины выполнены**:

| Критерий | Статус |
|----------|--------|
| Добавление товара в корзину | ✅ |
| Изменение количества / удаление | ✅ |
| Расчёт итоговой суммы | ✅ |
| Сохранение между перезапусками | ✅ (DataStore) |

**Оставлено на потом** (не блокирует переход к Спринту 6, можно добрать параллельно):

1. Синхронизация корзины с сервером (нет готового backend API).
2. Оставшиеся use cases как отдельные классы: `GetCartUseCase`, `RemoveFromCartUseCase`, `UpdateCartItemQuantityUseCase`.
3. Merge гостевой корзины (`userId = 0`) в корзину пользователя при входе.
4. Перенос с DataStore на Room (сущности `CartEntity` / `CartProductEntity` уже в схеме, DAO не подключены).

**Рекомендация:** считать Спринт 5 **условно завершённым по MVP** и начинать Спринт 6 (оформление заказа), а пункты из списка «на потом» — как техдолг или мини-инкременты между спринтами.

После первого инкремента корзина работала **только в памяти процесса** — при перезапуске приложения содержимое терялось. Во втором инкременте нужно было:

1. Добавить **локальное сохранение** без тяжёлой миграции Room.
2. Начать вынос операций в **domain use cases** (симметрия с auth и catalog).
3. Сохранить **небольшой объём изменений** — без API и без полного рефакторинга `CartViewModel`.

## Выполненные задачи

### 1. Локальное хранилище корзины (DataStore)

**Новые файлы** в `core/datasource/local/.../source/cart/`:

| Файл | Назначение |
|------|------------|
| `CartSnapshotDto.kt` | Serializable DTO для JSON-снимка корзины |
| `CartLocalSource.kt` | Интерфейс + реализация: load / save / clear |

**Механизм:**

- Ключ в DataStore: `cart_snapshot_{userId}` (отдельный снимок для гостя и для каждого пользователя).
- Формат: JSON через `kotlinx.serialization` (`productId`, `quantity`, `date`, `userId`).
- Используется тот же `PreferenceHelper` / `local_preferences`, что и для сессии пользователя.

**Обновлён:** `core/datasource/local/.../di/LocalDataSourceModule.kt` — регистрация `CartLocalSource` в Koin.

### 2. Репозиторий: память + диск

**Обновлён:** `core/data/.../repository/CartRepositoryImpl.kt`

- При чтении: сначала кэш в `ConcurrentHashMap`, при промахе — загрузка из `CartLocalSource`.
- После add / update / remove: `persistCart()` — запись в память и DataStore; при пустой корзине — удаление ключа.
- `clearCart` и `refreshCarts` согласованы с диском (очистка / перечитывание).

**Обновлён:** `core/data/.../di/DataModule.kt` — `CartRepositoryImpl(localSource = get())`.

## Как проверить

1. Добавить товар в корзину с экрана детализации.
2. Открыть корзину — позиции и суммы на месте.
3. **Полностью закрыть приложение** и открыть снова.
4. Открыть корзину — **товары должны остаться** (для того же пользователя / гостя).
5. «Очистить корзину» — после перезапуска корзина пуста.

## Известные ограничения

1. **DataStore, не Room** — для MVP достаточно; при росте каталога/истории заказов Room даст запросы и связи с заказами.
2. **Гость и пользователь** — разные ключи (`0` vs `profile.id`); при логине корзины **не сливаются**.
3. **Не все use cases выделены** — ViewModel корзины частично зависит от `CartRepository` напрямую.
4. **Нет серверной синхронизации** — ожидаемо до появления API.
